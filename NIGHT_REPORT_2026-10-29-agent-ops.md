# NIGHT_REPORT 2026-10-29 · возможности агентов, делегирование, ресурсы

Ветка `build/2026-10-29-agent-ops`, слита в `build/2026-10-25-tech-radar` (рабочая копия, с которой
работает сервер 4317). В `main` не сливалось: туда ещё не слита сама ветка tech-radar.
Подробное описание: `docs/agent-capabilities-and-delegation.md`.

## Что работает

- Каталог `agent_capabilities` / `GET /api/agent-ops/catalog`: исполнители, группы моделей, MCP-инструменты,
  сервисы, агенты-приложения; у каждой записи registered / discovered / available / verified с источником и временем.
- Маршрутизатор исполнителей (жёсткий фильтр пригодности, затем локальный → Codex → Claude) поверх
  существующего семантического выбора моделей; платные API не используются.
- Общий журнал квот (поручения + чаты по подписке): вход, квота, частота, следующая попытка, источник, срок
  актуальности; общий предел одновременных подписочных запусков.
- Диспетчер ресурсов с атомарными резервами GPU/VRAM/RAM/CPU/диска, резервом владельца, обучением оценок по
  измерениям, сверкой истёкших резервов. FLUX.3, Qwen edit, локальные LLM, H3, апскейл работают внутри резерва.
- Режимы компьютера + расписание Europe/Moscow + ручной режим; приложения владельца (Blender, UE, TouchDesigner,
  AE, рендер…) в фоновом режиме останавливают выдачу тяжёлой работы.
- Долговечная очередь поручений: блокировки рабочих копий, worktree, приоритеты со старением, защита от
  повторов и дубликатов, глубина/бюджет/циклы, проверка результата командами и файлами, восстановление после
  перезапуска без слепого повтора, «Остановить все задачи» отменяет управляемые поручения.
- Исполнители: `codex_cli` (workspace-write в песочнице Windows владельца), `claude_code` (только файловые
  инструменты и тестовые команды, acceptEdits, без bypass), `local_route` (ORP `ai.text`).
- Мастерская: статус-панель в шапке на всех вкладках; во вкладке «Агенты» — «Диспетчер задач агентов»
  (причины ожидания, результат, события, журнал, отмена/решение, исполнители, резервы, блокировки, расписание).
- Каждый MCP-клиент получает инструкцию в `instructions` и идентичность из `clientInfo`; дочерние исполнители —
  id, бюджет и подписанный токен; задачи PersonaCore и приложения Tove/Factory/Buzha — переменные окружения.

## Что проверено

- `vitest src/agent-ops`: 30 тестов (режимы и Moscow, атомарность VRAM, owner_busy, приложения владельца,
  измерения, квоты, блокировки, маршрутизация, очередь: проверка по файлам, ложный «успех», идемпотентность,
  дубликаты, одна рабочая копия, один GPU, fallback после лимита без двойного выполнения, частичные изменения,
  честное ожидание/блокировка, циклы/глубина/бюджет, перезапуск, токены, калибровка резерва RAM).
- Весь набор сервера: 706 из 720; 14 падений — те же файлы, что падают и до изменений (bonsai2, local-openai,
  libraries, node-packages, prompt-library, model-routing-integration; порты/реестр эндпоинтов окружения).
  Launcher: 8/8. `tsc --noEmit` сервера и лаунчера чистые.
- Реально, одноразовые проекты, ограниченный бюджет:
  - Codex (`agent-ops-smoke.ts codex`): verified за 22 с, изменён только `math.js`, независимый `node --test` прошёл.
  - Claude Code (`agent-ops-smoke.ts claude`, лимит Codex симулирован): маршрутизатор выбрал Claude, verified за 16 с.
  - Новый MCP-агент на живом 4317 (`agent-ops-mcp-smoke.ts delegate`): инструкция пришла сама, каталог,
    второй тяжёлый резерв отклонён, owner_busy отклоняет тяжёлую работу, агент не может менять режим,
    повтор idempotencyKey не запускает второй раз, задача ушла в Codex и verified (+ независимый тест).
  - Перезапуск через лаунчер (`... restart`): задача сохранилась, попыток выполнения не появилось.
- Живой прогон нашёл и исправил две ошибки: резерв RAM 8 ГБ блокировал даже лёгкий CLI (на машине 4,7 ГБ
  свободно из 32); Codex с `--ignore-user-config` терял песочницу Windows `elevated` и молча работал read-only
  (проверки SnarkRoute это поймали — задача ушла в failed, а не в «готово»).

## Не проверено или ограничено

- Локальный исполнитель вживую не запускался: в каталоге нет доступной локальной текстовой модели
  (Ollama/Bonsai не готовы); путь покрыт тестами с подменой. Задача для него честно блокируется с причиной.
- Реальные лимиты подписок не исчерпывались — только симуляция (`/api/agent-ops/simulate`).
- Обрыв связи посреди реального запуска CLI и сверка живого pid после перезапуска проверены тестами, не вживую.
- PersonaCore и Tove/Factory/Buzha получают переменные окружения, но их код (отдельные репозитории) их пока
  не читает — нужна строка в их системных промптах.
- HTTP API по-прежнему доверяет любому локальному процессу без токена как владельцу.
- Photoshop исключён из списка «тяжёлых приложений владельца» (всегда открыт и сам клиент SnarkRoute);
  список меняется в `apps/server/data/agent-ops/computer-mode.json` (`ownerApps`, `ownerAppsCustomized: true`).
- Расписание не задано (свободных часов владельца я не придумывал): действует «Можно работать в фоне».
