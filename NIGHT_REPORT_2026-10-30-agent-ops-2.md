## Сделано

### Сервер SnarkRoute (ветка, не слита)
- **HTTP без идентификации.** Отсутствие токена — роль `anonymous`, только чтение. Владелец — сессия
  Мастерской (выдаётся странице на origin лаунчера) или Bearer токена лаунчера. Агент через HTTP и MCP
  не меняет режим/расписание/пределы, не запускает симуляции, не видит чужие задачи, результаты и журналы,
  не повышает приоритет сверх политики, не выходит за разрешённые папки. Токен агента ставит контекст
  «агент» на любой запрос к SnarkRoute: прямые вызовы маршрутов и Model Gateway подчиняются режиму и резервам.
  Неверный токен — 401. Продление токена запущенного агента, предпросмотр решения диспетчера без резерва.
- **Секреты владельца** (токен лаунчера, MCP-токен) убраны из окружения Codex/Claude-исполнителей,
  проверок и PersonaCore.
- **Занятость по нагрузке.** Счётчики Windows: загрузка движков GPU и выделенная VRAM по процессам,
  CPU по процессам и общий, командные строки рендеров (aerender, Blender -b, UnrealEditor-Cmd и др.).
  Открытое простаивающее приложение — только сигнал. Рендер, активное приложение владельца (включая
  Photoshop по его потреблению) или сильная нагрузка от незнакомого процесса держат тяжёлую фоновую работу,
  в том числе в ночном окне. Нагрузка неизвестна — в фоне консервативный отказ с причиной.
  Ручной режим остаётся главным.
- **Границы учёта квот.** Отдельно: измерено через SnarkRoute (поручения и чаты, токены), отчёт провайдера
  о тарифе (включает внешнее использование, со сроком актуальности), внешнее использование — «не
  наблюдается», наши пределы параллельности и дневные. Показано в API и Мастерской.
- **Мастерская:** сессия владельца, занятость по замерам, границы квот, история приёмки.
- **Приёмщик.** Я сделал свой, но в итог он не пойдёт: в рабочей копии и на живом сервере работает
  приёмщик Codex (контракт с критериями, журнал внешних эффектов, пауза, уточнение задачи), шире моего
  и с тестами по каждому сценарию пункта 6. Чтобы не было двух механизмов, при переносе остаётся его.

### Агенты
- **Шорёк:** токен на всех вызовах SnarkRoute; `gpu_allowed` спрашивает диспетчер; тикеты Codex/Claude —
  долговечные задачи общей очереди с повторным подключением по ключу; без токена ничего не запускается
  напрямую; прямой обход SnarkRoute к Ollama выключен (именно он загрузил `llama3` в 23:03).
- **Фабрика:** токен; планировщик и адаптеры GPU-задач подчиняются «эффективному режиму» с учётом
  диспетчера; эндпоинты `/api/agent-ops`, `/api/agent-ops/delegate`, `/api/agent-ops/tasks/{id}`.
- **PersonaCore:** токен на шагах модели, краткая инструкция системным сообщением, инструменты
  `snarkroute.capabilities / delegate / task / computer`; файловая работа только внутри своей папки и
  только с разрешением на запись.
- **Бужа:** токен на запросах чата; поручения исполнителям из интерфейса и `/api/delegate`; её скрипты
  `Run-Codex-Task.ps1` и `Run-Claude-FL-Repair.ps1` больше не запускают CLI напрямую, а отправляют задачу
  в общую очередь. Codex уже переносит эту интеграцию в копию Бужи в репозитории и дополняет её.
- Общий клиент `snarkroute_agent_ops.py` одинаковый во всех четырёх (только стандартная библиотека).

## Важно знать

- **Ollama запущен по моей ошибке:** команда `ollama list` в 23:03 сама подняла сервер Ollama, который был
  остановлен. Чужих моделей я не выгружал. После проверки локальной модели верну исходное состояние.
- **Квота Claude:** по отчёту провайдера использовано 92 % окна тарифа. Реальные запуски Claude ограничиваю.
- **Остаточная граница доверия:** сессию владельца получает браузер на origin Мастерской. Локальный
  процесс, намеренно подделывающий заголовки браузера, обойти это может: на одной учётной записи Windows
  секрет нельзя полностью скрыть от процесса того же пользователя. Агенты по протоколу получают только
  свой токен.
- **Вызовы без токена от незнакомых локальных клиентов** (Mixar, панели Adobe) к модельным маршрутам
  по-прежнему считаются интерактивными запросами владельца — чтобы не сломать их. Права управления
  агентами, задачами, ресурсами и режимом они не получают.
