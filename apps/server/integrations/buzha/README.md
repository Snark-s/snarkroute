# Бужа в SnarkRoute

Постоянный агент `app:buzha` работает в общей очереди SnarkRoute и проходит общий
Приёмщик. Открытие: Мастерская → «Агенты» → «Бужа» (`http://127.0.0.1:5172/buzha`,
порт берётся из `service-endpoints.json`). Чат создаёт сохраняемое поручение;
в карточке видны фактические модель/провайдер, инструменты, решения, доказательства
и пауза, продолжение, отмена. Держать открытый чат Codex не требуется.

Этот каталог — исходники существующего бюро `Y:\Приложения\Бужа`:
`server.py`, `index.html`, `snarkroute_agent_ops.py`. Бюро на зарегистрированном
порту 8796 сохраняет учёт заказов, заданий, сообщений, стоимости и предыдущих
делегирований. Его чат тоже передаёт работу общей очереди. `ready` у бюро
по-прежнему означает доступность его интерфейса; приёмка подтверждается только
`verified` у общей задачи. `automation=false` означает отсутствие локального
владельца расписаний и не отменяет исполнение явных поручений.

Каноническая личность, аккаунты, рабочие материалы и изображения находятся в
существующем приложении. SQLite `data/buzha.sqlite3` сохраняется, добавлена только
таблица связей `agent_work`; повтор requestKey не создаёт второе поручение.
Обновление не заменяет базу, identity.md, аккаунты или assets. Резервная копия
предыдущего сервера, страницы, SDK и согласованная копия SQLite находятся в
`.backup-2026-10-30-acceptor` рядом с приложением.

Исполнитель использует Model Gateway: подходящая локальная модель, разрешённые
Codex/Claude подписки для сложной работы, обычные leases, квоты, блокировки и
бюджеты. Выбор модели не меняет личность или полномочия. Историческая настройка
OpenRouter сохранена, но постоянный исполнитель API автоматически не включает.
Структурированный цикл инструментов реально вызывает SnarkBridge, возвращает
наблюдения модели и записывает ответ внутри папки задачи. Рабочая сессия браузера
— существующий подтверждённый Chrome Profile 13. Инструменты чтения доступны
в рамках прежней политики; коммерческие отправки, смена профилей, платежи,
регистрации, пароли и CAPTCHA этим контуром не выполняются.

Две включённые по сведениям владельца автоматизации остаются в **ChatGPT**:
«Бужа: поток заказов» — каждый час в :07:50 МСК, точное расписание;
«Бужа: ответы и сделки» — 22:30 Europe/Stockholm, гибкий запуск (зимой 00:30 МСК
следующих суток, летом 23:30 того же дня). Их идентификаторы и исходные настройки
сохранены в `settings.agent_schedule`; локальное исполнение выключено.
Миграция не объявляется завершённой, пока обе стороны не согласованы.

Запуск и остановка бюро — штатные `POST /api/system/apps/buzha/start|stop` в
SnarkRoute. Остановка проходит через identity-проверенный локальный shutdown,
без завершения чужих PID по порту. При обновлении остановить простаивающее бюро,
скопировать три исходных файла и запустить его снова; SQLite не заменять.
Python 3.10+, дополнительных библиотек для бюро не требуется. Единственный
источник адресов/портов — реестр сервисов. Секреты провайдеров бюро не получает.

HTTP `/api/agents/buzha`, `/messages`, `/tasks/:id` и действия
`pause|resume|cancel|continue`; MCP `buzha_message`, `buzha_status`, `buzha_task`,
`buzha_control`. Каталог: `tools:buzha`. Полный контракт и граница миграции:
`Y:\Процесс\SnarkRoute\docs\buzha-agent.md`; общий Приёмщик:
`Y:\Процесс\SnarkRoute\docs\agent-acceptor.md`.

Проверки бюро: `python -m unittest test_server test_agent_runtime` в каталоге
интеграции (временная SQLite, без коммерческих действий). Сквозные испытания:
`apps/server/scripts/buzha-tools-smoke.ts`, `buzha-mcp-smoke.ts`,
`buzha-restart-smoke.ts`. Последний перезапускает только простаивающий штатно
управляемый SnarkRoute и сверяет историю, доказательства и сохранённую паузу.
