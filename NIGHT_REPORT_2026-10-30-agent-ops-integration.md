## 2. Что реализовано

Ветка `build/2026-10-30-agent-ops-integration` (worktree `.claude/worktrees/ops-int`) построена от коммита Codex.
За основу взяты Приёмщик, контракт, pause/resume/amend/effects и исполнение Бужи из `8ea9fae1`. Моя конкурирующая
реализация приёмки (`acceptance.ts`, состояние `awaiting_acceptance`) удалена, имена состояний — как у Codex.

- **Учёт времени** (`time-budget.ts`, `tasks.ts`).
  - Ожидание очереди, окна, ресурсов и квоты бюджет не тратит.
  - Активное время — это состояние `running` плюс `reviewRuns` Приёмщика.
  - Общий бюджет цепочки суммирует активное время всех задач цепочки.
  - Явный `deadline` идёт всегда.
  - `timing` хранится в задаче и накапливается при каждой смене состояния, поэтому переживает перезапуск.
  - `timeLeftMs` используется при запуске, для таймаута исполнителя и для таймера проверки Приёмщика. При
    исчерпании Codex-овский `blockBudget` ставит задачу в `blocked` с причиной.
- **Полномочия.**
  - Без учётных данных — аноним, только чтение.
  - Чужие задачи и результаты не читаются: `requireReadable` в HTTP и MCP, включая acceptor inspect.
  - Heartbeat резерва принимается только от его владельца.
  - Origin, Referer и Host прав не дают.
- **Вход владельца.**
  - Лаунчер запрашивает одноразовый код: 2 минуты, гасится один раз, хранится хэш, в журналы не пишется.
  - Код передаётся во фрагменте URL. Страница обменивает его на сессию и вызывает `history.replaceState`.
  - Сессии привязаны к эпохе; `POST /owner-session/revoke-all` отзывает их все.
  - Кнопка «Войти как владелец» есть в панели агентов; Бужа использует те же заголовки.
- **Mixar и панели Adobe.** Их код не менялся. Вызов модели или GPU без токена сервер приписывает процессу через
  `netstat` и дерево родителей:
  - дерево агента или Codex/Claude CLI — работа агента, с режимами и резервами;
  - программа владельца (Photoshop, AE CEP, Mixar, браузер…) — интерактивный клиент, может только запускать модели;
  - оборванная цепочка без программы владельца — фоновая работа.
- **Занятость компьютера** (`activity.ts`).
  - Учитываются счётчики GPU, VRAM и CPU по процессам и командные строки рендеров.
  - Открытое простаивающее приложение — только сигнал.
  - Реальная нагрузка, рендер или CPU ≥ 75 % означают «занят».
- **Квоты.** В ledger отдельно видны измеренное SnarkRoute, отчёт провайдера по всему плану, внешнее использование
  (не наблюдается) и наши пределы. Учитываются и поручения, и ходы чата.
- **Документация** `docs/agent-capabilities-and-delegation.md`: роли, вход, граница для вызовов без токена, время,
  занятость. Устаревшие строки в «Границах» исправлены.
