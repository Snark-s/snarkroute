# Технорадар — отчёт 25 октября 2026

MVP реализован, проверен на живом Maestro и подключён к рабочему API. После
прямого разрешения владельца выполнен перезапуск через существующий лаунчер.
`/api/tech-radar` отвечает 200; лаунчер показывает новый PID 45216 и состояние
`healthy`. Браузер проверен уже на основном каталоге. Тестовое решение осталось
только в копии, решение владельца в основном каталоге не подменялось.

## Реализовано

- Русский раздел `/tech-radar` в SnarkRoute Living Canvas и BoojumRoute: приём
  GitHub-ссылки, состояния очереди, каталог, поиск, фильтры, карта возможностей,
  подробная карточка, первоисточники, история, решения и комментарии.
- Нормализация ссылки и постоянная идентичность проекта. `.git`, регистр и
  ссылки на файлы не создают дубликат. Повторное исследование сохраняется
  внутри прежнего проекта.
- Публичный GitHub-коллектор: метаданные, README, структура, релизы, issues,
  лицензии, зависимости и выбранная документация. Фиксированный API-host,
  запрет redirects/небезопасных URL, ограничения размера/времени/запросов,
  постоянный кеш и условные запросы ETag.
- Анализ через существующий адаптер радаров и подписки. Codex добавлен в этот
  адаптер с повторным использованием обнаружения CLI. Claude доступен как
  явный выбор. Платного fallback нет. Промпт не получает `.env`, секреты,
  содержимое локальных настроек и пути к ним. Инструменты анализа отключены.
- Структурированные находки, связи проектов и возможностей, уровни
  подтверждения, сравнение с зарегистрированными инструментами. Каталог
  различает документацию, заявления и интерпретации. Неподтверждённые цитатами
  выводы становятся неизвестными, неподтверждённые возможности исключаются.
- Отдельные рекомендация и пользовательское решение. «Подготовить тест»
  сохраняет решение и позволяет открыть конкретный план; установка и генерация
  не запускаются. «Внедрение рассмотреть отдельно» не выполняет внедрение.
- Постоянная очередь с последовательной обработкой, атомарными JSON-снимками,
  резервным снимком и процессной блокировкой. После перезапуска незавершённое
  исследование продолжается с сохранённых источников. Предыдущие успешные
  результаты не теряются при ошибке повторного анализа.
- Наблюдение за проектами «Следить», выключенное по умолчанию. Периодические
  проверки используют существующий планировщик радаров с пустым списком платных
  радаров. Уведомления внутри интерфейса появляются при существенных изменениях.
- API и MCP-инструменты `tech_radar_research`, `tech_radar_catalog`.

## Контрольный пример Maestro

Исследование выполнено самим инструментом через GitHub и Codex по подписке.
В каталоге один проект, одно успешное исследование, 13 полученных источников;
версия из VERSION — 3.2.5. Неудачные попытки сохранены в истории: лимит Claude,
нарушение схемы и неточная цитата. После исправлений полный цикл завершился.

Результат определяет Maestro как локальную AI-студию с видео, изображениями,
музыкой, речью и редактором. Практический интерес выделен в Director Mode:
музыкальный анализ, редактируемый план кадров, генерация нескольких клипов,
повтор отдельного клипа и сборка результата. Эти выводы не зашиты для Maestro;
контрольная ссылка присутствует только в smoke-скрипте.

Пересечения найдены с FLUX.3 Native, Qwen Image Edit, MiniMax H3, YuE2,
Local Upscale, Video Upscale и Factory. Новые для текущего неполного каталога:
планирование кадров под музыку, раскадровка, автоматический монтаж,
сохранение идентичности персонажей и локальный TTS. Это не доказательство,
что аналогов нет в остальных инструментах мастерской.

Рекомендация — **«Испытать»**. План включает некоммерческий музыкальный фрагмент
30–45 секунд, ручное утверждение плана, три пробных клипа, измеримые критерии
синхронизации/непрерывности/стабильности, оценку памяти, изоляцию и удаление
эксперимента. План не выполнялся. Наличие документированного HTTP API отражено
в карточке; готовая совместимость со SnarkRoute/SnarkBridge не заявляется.

Карточка отдельно рассматривает ограничения приложения и весов. В частности,
[корневая лицензия](https://github.com/Blizaine/Maestro/blob/main/LICENSE)
описывает некоммерческое использование приложения и отдельное коммерческое
лицензирование; условия outputs и отдельных моделей требуют самостоятельного
рассмотрения. Учтены также
[THIRD_PARTY_NOTICES](https://github.com/Blizaine/Maestro/blob/main/THIRD_PARTY_NOTICES.md)
и README. Это пересказ первоисточников, не юридическое заключение.

## Проверки

**55 автоматических тестов прошли:** 54 серверных в шести сфокусированных файлах
и один UI-тест. Покрыты безопасные/некорректные URL, HTTP 302/404/429/500,
невалидный JSON, кеш и ETag, приоритет лицензий/Director docs, повторы,
параллельная постановка, сохранение решений, повторное открытие хранилища,
восстановление очереди, ошибки модели, повреждённый каталог, блокировка второго
процесса, выключенное наблюдение, проверка цитат, отсутствие платного fallback,
изоляция учётных данных и локальный callback общего планировщика.
В автоматических тестах GitHub и модели мокированы.

Проверены типы сервера, Studio и SnarkRoute. Сборки сервера и обоих Vite-интерфейсов
прошли. Vite сообщает о крупных существующих JS chunks; UI-тест также сообщил о
занятом WebSocket-порту временного стенда, завершившись успешно.

Живой smoke подтвердил получение источников и анализ Maestro. Отдельный процесс
повторно открыл реальный каталог, проверил все сохранённые ссылки/цитаты и
дедупликацию без нового задания. Короткий дополнительный вызов подтвердил работу
Codex после исключения refresh token из временного входа. Временный auth.json
удалён. Платные API и GPU не использовались.

В браузере на копии каталога проверены карточка, карта возможностей, сохранение
решения «Подготовить тест», сохранность после reload и повторная `.git`-ссылка
без второго проекта. Тестовое решение осталось только в копии; в основном
каталоге решение владельца отсутствует. После подключения API карточка повторно
открыта в обычном SnarkRoute: основной каталог содержит Maestro, рекомендацию
«Испытать» и пользовательское решение «Ещё не принято». Итоговый снимок рабочего
интерфейса: `reports/tech-radar-preview.jpg`.

Первый штатный перезапуск получил `Graceful stop timeout`: прежний API PID 16956
закрыл порт, но не завершился. После проверки идентичности процесса, владения
лаунчером и свободного порта завершён только этот зависший процесс API; лаунчер
запустил замену. Прочие службы и воркеры не останавливались. Причина зависания
старого процесса в рамках этой задачи отдельно не исправлялась.

Финальная проверка рабочего API: `/health` и `/api/nodes` — 200, запрос MCP без
авторизации — 401. Повторная постановка Maestro через реальный HTTP API вернула
200 и `duplicate: true`; осталось один проект, пять записей попыток, одно успешное
исследование, ноль решений владельца; наблюдение выключено.

## Где открыть и что ещё требуется

Обычный SnarkRoute → «Технорадар» или
`http://127.0.0.1:5174/tech-radar`. В BoojumRoute: `/tech-radar` на его порту.
Инструкция: `docs/tech-radar.md`. Основные данные: `data/radars/tech-radar/catalog.json`.

Открытый браузер показывает рабочий интерфейс с основным каталогом, временный
проверочный стенд остановлен. Пункт 12 задания соблюдён: согласие на перезапуск
запрошено после реализации, проверок и подготовки отчёта, и получено явно.

Ограничения MVP: только публичный GitHub; выборочная документация и issues;
неполный реестр мастерской; зависимость анализа от действующей подписки;
JSON-хранилище для одного владельца; отсутствие внесения протокола успешного
локального теста и подтверждённого «Внедрить». SnarkBridge во время первоначальной
проверки не отвечал, его работоспособность не выдумывалась. Сам Maestro не
устанавливался, его генераторы не запускались.

Следующий этап: внести протоколы локальных экспериментов и доказательства улучшений,
расширить инвентаризацию DCC/провайдеров, добавить другие источники и при росте базы
перейти на SQLite. Автоматическое внедрение в этот MVP не входит.
