# Проверка SnarkBridge без изменения системы

Из корня действующей локальной установки SnarkRoute:

```powershell
node scripts/diagnose-snarkbridge.mjs
```

Скрипт использует существующий реестр сервисов, делает только GET-запросы
к двум зарегистрированным loopback endpoint и ничего не перезапускает.
Он не читает Chrome, пароли, ключи, окружение с секретами или тела ошибок.
Нет новых портов, внешних запросов или изменений разрешений.

- `mcp.state=verified`: локальный MCP отвечает с ожидаемой идентичностью и API.
- `tunnel.state=local_ready`: локальная проверка готовности туннеля вернула HTTP 200.
- `http_error` и `httpStatus`: endpoint доступен, но отверг запрос. Сам HTTP 429
  не объясняет причину и не доказывает блокировку сайта.
- `unreachable`: запрос не завершился успешно; см. локальные журналы.
- `cloud.state=unverified`: требуется отдельный успешный вызов `bridge_status`
  именно из ChatGPT. Локальный HTTP 200 не заменяет такую проверку.

Коды завершения: 0 — обе локальные проверки прошли (облако ещё не подтверждено),
1 — локальная проверка не прошла, 2 — ошибка реестра.

При ошибке `CONNECT_SNARKBRIDGE.ps1:36` нужны строки диагностики **перед**
`Tunnel diagnostics failed`, а также актуальные версии скриптов из каталога
`paths.snarkbridge` действующего реестра. В этом репозитории исходников
`CONNECT_SNARKBRIDGE.ps1`, `snark_services.ps1` и сервера SnarkBridge нет.
Не подменять их догадками, не удалять учётные данные туннеля, не отключать TLS,
проверку владельца или согласование доступа. Перед передачей журналов удалить
секреты, заголовки авторизации и URL с параметрами токенов.

Восстановление подтверждено только после успешного `bridge_status`, затем
`browser_sessions`, затем чтения вкладки именно профиля Бужа. Нельзя считать
облачный браузер ChatGPT этим локальным профилем.
