# Паспорт Мастерской

Версия паспорта: 2026-10-31.1 · сверено с живым каталогом 31.10.2026 · проверка: `node scripts/passport-check.mjs`

Мастерская — система агентов Сергея Козинцева, которая доводит задачи до проверенного
результата без его участия. Это первый документ для любого агента (Codex, Claude Code,
ChatGPT, свои агенты). Прочитай его целиком перед проектированием, перед ответом
«это невозможно» и перед созданием нового реестра, подсистемы или функции.

Действующие решения владельца: [decisions/REGISTRY.md](decisions/REGISTRY.md).
Решение со статусом «принято» нельзя молча заменить своей идеей. Хочешь изменить —
предложи новое решение со ссылкой на старое.

## Главные решения (сокращённо)

- D-01 SnarkBridge — полный аналог Desktop Commander: что разрешено DC, разрешено мосту.
- D-02 Уровень 3 даёт агенту почти все права владельца; за владельцем только деньги.
- D-03 Лимитируется повтор бесполезного способа, а не работа над целью. Система сама
  ищет другой способ, инструмент или исполнителя. К владельцу — только за деньгами,
  решением владельца, внешним барьером (CAPTCHA, 2FA) или недобываемыми сведениями.
- D-04 Бужа может писать владельцу напрямую; всё поручаемое ей попадает в общий реестр.
- D-05 PersonaCore — только сведения о владельце. Общая память агентов — отдельно.
- D-06 Навыки = «функции». Новый параллельный каталог навыков не заводить.
- D-07 Шорёк мотивируется Shilo (скука); задачи приходят к нему как возможности.
- D-08 Фабрика непрерывно ищет и развивает источники дохода.
- D-09 Джабервок — независимый постоянный агент, не оболочка чата.
- D-10 Реестр моделей, исполнителей и ресурсов уже есть в SnarkRoute — встраивать, не изобретать.

## С чего начинать любую задачу

1. `agent_whoami` — своя идентичность и бриф; `agent_capabilities` — что есть сейчас.
   Каталог главнее этого паспорта: статусы registered/discovered/available/verified.
2. Нужен исполнитель — `agent_delegate_submit` с критериями и проверками; не отказывать.
3. Тяжёлая работа на GPU — `agent_resource_acquire`, режим компьютера уважать.
4. Подключаешь новое — `docs/CONNECTING-NEW-ENTITY.md`.
5. Изменил возможности системы — обнови этот паспорт и прогони `passport-check`.

## Известные дыры (план модернизации, этапы A–G)

- Приёмщик после `maxAttempts` ставит `blocked` — противоречит D-03 (этап C).
- SnarkBridge ограничен списком программ и разовыми подтверждениями — противоречит D-01 (этап B).
- Девять хранилищ задач вместо одного реестра; у Секретаря нет процесса (этап D).
- Восемь планировщиков и четыре правила денег (этап E).
