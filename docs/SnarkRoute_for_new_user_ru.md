# SnarkRoute: кратко для нового пользователя

## Что это такое

SnarkRoute — это визуальная студия для сборки AI/workflow-маршрутов из нод.  
Идея простая: вместо того чтобы вручную писать цепочки API-вызовов и скриптов, пользователь собирает процесс на canvas: ноды соединяются проводами, данные идут от входов к трансформациям, генераторам, превью и выходам.

Проект локально-ориентированный: маршруты можно собирать, сохранять, запускать и расширять установленными нодами.

## Что уже умеет

### 1. Визуальный canvas

Можно:

- добавлять ноды;
- двигать их по canvas;
- соединять output одной ноды с input другой;
- удалять ноды и связи;
- запускать маршрут;
- смотреть logs, results и preview.

### 2. Палитра нод

В Studio есть палитра нод с категориями.  
Ноды можно добавлять кликом или перетаскиванием.

Есть bundled-ноды, которые идут вместе с проектом, и installed-ноды, которые можно добавить отдельно.

### 3. Быстрое добавление совместимой ноды

Можно потянуть связь из output-порта и отпустить на пустом месте canvas.  
Studio покажет меню совместимых нод, а выбранная нода сразу добавится и подключится.

### 4. Сохранение и восстановление

Studio сохраняет текущую схему в browser localStorage.  
При перезапуске она автоматически восстанавливает последнюю локально сохранённую схему.

Важно: это пока не полноценное серверное хранение проектов.

### 5. Импорт и экспорт маршрутов

Поддерживаются route-файлы в форматах:

- `.orp`
- `.orp.json`
- `.orp.yaml`
- `.route`
- `.route.json`
- `.route.yaml`
- plain JSON/YAML

Маршрут можно импортировать, экспортировать или перетащить на canvas.

### 6. Установленные ноды

Studio умеет устанавливать ноды:

- из файла;
- из локального path;
- по URL;
- из node library.

Установленными нодами можно управлять: включать, отключать, читать README, удалять.

Bundled-ноды удалить нельзя.

### 7. Missing-node placeholders

Если маршрут использует ноду, которая не установлена или отключена, Studio не ломает маршрут.  
Она сохраняет экземпляр ноды как placeholder и показывает warning.

Это важно для переносимости: route не превращается в кашу, если на другой машине не хватает нод.

### 8. Compound / Subroute nodes

Выбранные ноды можно свернуть в compound node.  
Это превращает кусок графа в одну ноду с внутренним subroute.

Можно:

- Collapse выбранные ноды;
- открыть внутренний subroute;
- редактировать его;
- вернуться назад;
- выполнить compound node;
- Uncollapse обратно в исходные ноды.

Это позволяет строить маршруты высокого уровня, где сложные куски графа прячутся внутрь одной ноды.

### 9. Исполнение маршрутов

Execution engine умеет:

- определять порядок исполнения по graph dependencies;
- находить циклы;
- выполнять ноды;
- делать template interpolation вида `{{nodeId.output.path}}`;
- выполнять compound/subroute;
- собирать logs, results, provenance и cost usage metadata;
- сохранять результаты run.

### 10. Backend/API

Backend предоставляет API для:

- health check;
- settings и API tokens;
- каталога нод;
- установки node packages;
- route validation;
- route execution;
- runs/ledger;
- prompt library;
- assets;
- provider helpers.

## Из чего состоит проект

Основные части:

| Папка | За что отвечает |
|---|---|
| `apps/studio` | UI Studio, canvas, palette, context menu, save/load |
| `apps/server` | Fastify backend/API |
| `packages/protocol` | Формат route, import/export, validation |
| `packages/executor` | Execution engine |
| `packages/nodes` | Built-in nodes и package system |
| `packages/adapters` | Адаптеры внешних провайдеров, например Gemini/Replicate |
| `packages/storage` | Локальное хранение run results |
| `examples` | Примеры routes и custom nodes |
| `data/installed-nodes` | Установленные node packages |
| `docs` | Документация |
| `.codex` | Локальные инструкции/skills для Codex, не runtime продукта |

## Что можно показать в демо

### Демо 1: простой маршрут

1. Открыть Studio.
2. Добавить `Text Input`.
3. Добавить `Template Transform` или `Debug Log`.
4. Соединить ноды.
5. Запустить route.
6. Показать logs/results.
7. Сохранить и перезагрузить страницу.

Показывает базовый workflow: canvas, typed connections, run, logs, save/restore.

### Демо 2: installed node

1. Открыть Settings -> Node Packages.
2. Установить custom node из `examples/custom-nodes`.
3. Добавить ноду на canvas.
4. Запустить или провалидировать route.
5. Отключить или удалить установленную ноду.
6. Показать missing-node placeholder.

Показывает расширяемость проекта.

### Демо 3: compound/subroute

1. Собрать маленькую цепочку из двух-трёх нод.
2. Выделить часть графа.
3. Collapse в compound node.
4. Открыть subroute.
5. Изменить внутренний граф.
6. Вернуться назад.
7. Запустить parent route.
8. Uncollapse обратно.

Показывает, что SnarkRoute может работать не только с простыми цепочками, но и с вложенными графами.

## Что пока слабое или требует доработки

- В палитре есть категории, но нет полноценного поиска.
- Dirty state реализован частично: нет очевидного постоянного индикатора.
- Compound port editing пока rough, через browser prompts.
- Generic `declarative` executor выглядит не до конца поддержанным; `declarative.http` работает.
- Provider demos требуют токены Gemini/Replicate или локальный Stable Diffusion endpoint.
- Studio save/load пока использует localStorage, а не серверное хранение проектов.
- Visual clarity нужно проверять вживую в браузере.

## Главная мысль для новичка

SnarkRoute — это не просто “нодовый редактор”.  
Это попытка сделать открытую систему маршрутов, где AI-инструменты, локальные процессы, внешние API, промпты, ассеты и пользовательские ноды можно соединять в понятные визуальные пайплайны.

Если совсем коротко:

> SnarkRoute — это мастерская маршрутов: собираешь процесс из нод, запускаешь, расширяешь своими нодами и постепенно превращаешь хаос AI-инструментов в управляемую схему.
