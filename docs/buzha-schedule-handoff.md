# Согласование источника расписаний Бужи

Состояние: подготовлено, **не активировано**. Владелец — ChatGPT Automations,
`localEnabled=false`. Два существующих ID, расписания и режимы не менять;
новых автоматизаций и локальных scheduler jobs не создавать.

Живая проверка `scripts/buzha-schedule-mcp-smoke.ts` из `apps/server` подтвердила:
MCP и HTTP дают один ключ для времени UTC и Moscow, до согласования `accepted=false`
и задача не создаётся. Это не доказывает доступность MCP внутри ChatGPT Automation.

## Порядок согласования

1. Прочитать именно две существующие автоматизации и сохранить их инструкции,
   ID, включённость, DTSTART/RRULE, исходные timezone и exact/flexible режимы.
2. Проверить там доступность `buzha_schedule_trigger` и фактический MCP client id.
   Вызвать только `dryRun:true`. Если инструмента нет, сохранить нынешнее исполнение;
   локальную замену не включать.
3. Сверить внешние исполнения и неизвестные отправки, дождаться окончания или
   независимо установить исход. Чужие задачи не отменять.
4. Сохранив назначение каждой автоматизации, изменить только исполнение на передачу
   постоянной Буже. До окончания согласования источник должен ждать без собственных
   коммерческих действий. Прежний самостоятельный проход площадок не выполняется.
5. Проверить обе сохранённые инструкции и отсутствие незавершённых внешних действий.
   Только после этого владелец вызывает `POST /api/agents/buzha/schedules/handoff`:

```json
{
  "sourceClientId": "mcp:<фактически проверенный клиент>",
  "verifiedBothSides": true,
  "noUnfinishedExternalEffects": true,
  "proof": "Конкретные проверенные ID, изменения инструкций, время и результаты сверки внешних исполнений. Не заполнять предположением."
}
```

Endpoint сохраняет подтверждение владельца, а не умеет самостоятельно читать
ChatGPT. Флаги без реальной проверки передавать нельзя. Live handoff сейчас не
вызывался. После согласования `owner=chatgpt`, `localEnabled=false` сохраняются:
ChatGPT владеет временем, общая очередь — исполнением.

## Текст передачи для существующих автоматизаций

Добавить к сохранённому назначению каждого задания:

> Единственный исполнитель рабочего поручения — постоянная Бужа SnarkRoute.
> Вызови buzha_schedule_trigger с ID этой автоматизации, номинальным scheduledFor
> исходного срабатывания с часовым поясом и полным рабочим поручением в content.
> Почасовая задача использует соответствующее :07:50, ежедневная — 22:30
> Europe/Stockholm на исходную дату, даже если flexible-запуск запоздал.
> Прочитай accepted и task.id. При accepted=false самостоятельную работу на
> площадках не выполняй: передача не согласована, сохрани причину.
> При потере ответа повтори те же ID, scheduledFor и content, не время повтора.
> Для созданной задачи используй buzha_task. Не отправляй сообщения параллельно.

После согласования проверить одно настоящее срабатывание: одна задача, реальные
инструменты, общий Приёмщик, результат в канонической переписке. Повторить запрос
через второй транспорт и после рестарта. До этого миграция не завершена.
