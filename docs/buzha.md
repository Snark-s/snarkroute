# Бужа в Мастерской

Бужа — локальное бюро разовых заказов: учёт, вручную внесённые задания и чат
без инструментов. `ready` означает доступность интерфейса. `automation` всегда
`false`. Автопоиск, почта, Telegram, выполнение заказов, кошелёк и фоновое
расписание не реализованы. Вопросы будущего исполнителя должны идти через
Секретаря; записи раздела «Задания Сергею» сейчас создаёт сам пользователь.

## Установка и адреса

Развёрнутое приложение: `Y:\Приложения\Бужа`. Исходники доработанного сервера
и страницы находятся в `apps/server/integrations/buzha/`; изображения остаются
в `assets/` приложения. Для обновления остановить Бужу в Мастерской, скопировать
`server.py` и `index.html` из этой папки и запустить её снова. Python 3.10+,
без дополнительных библиотек. SQLite и изображения при обновлении не заменяются.

Единственный источник портов — `service-endpoints.json`: сервис `buzha`, HTTP,
`/api/health`, identity `service=buzha`, `watch=always`; каталог — `paths.buzha`.
Путь к реестру переопределяет `SNARKROUTE_PORT_REGISTRY`. Приложение отвергает
неверный host, нечисловые и дублирующиеся порты; переменной `BUZHA_PORT` нет.
После изменения реестра перезапустить затронутые службы.

Запуск: `python server.py --no-browser` через общий скрытый launcher. Журнал:
`data/logs/buzha.log` рядом с приложением; он доступен в терминалах Мастерской.
Отдельная копия `assets/buzha.png` опубликована как `/buzha-icon.png` в общем
public-каталоге лаунчера `apps/snarkroute/public/` (см. его Vite-конфигурацию).

## Жизненный цикл

- `GET /api/system/apps` — реальная карточка с `id=buzha`, `controllable=true`.
- `GET /api/system/apps/buzha/status` — identity-проверенное состояние.
- `POST /api/system/apps/buzha/start|stop|open` — управление и открытие.
- `local_runtime_status|start|stop`, runtimeId `buzha` — те же операции через MCP.
- «Остановить все задачи» вызывает безопасные контроллеры локальных процессов,
  включая Бужу. Отказы возвращаются отдельно; процессы без контроллера пропускаются.

Остановка Бужи проходит через её собственный `/api/system/shutdown` с токеном
сессии после проверки health. Завершения по занятому порту или чужому PID нет.
`stop-snarkroute.ps1` также сначала запрашивает эту остановку через SnarkRoute.
Сам перезапуск SnarkRoute не завершает отдельное приложение Бужи.

## Разговор и стоимость

В «Подключениях» пользователь выбирает модель из текущего каталога SnarkRoute.
Секреты и адреса провайдеров приложению не передаются. Старые переменные
`BUZHA_CHAT_URL`, `BUZHA_CHAT_KEY`, `BUZHA_CHAT_MODEL` больше не используются.

Путь: Бужа → `/api/system/buzha/chat/completions` → `/api/routes/run` → существующий
`ai.text` Model Gateway → выбранный адаптер. `/api/model-gateway/jobs` сейчас
поддерживает медиа, поэтому для текста используется действующий исполнитель
маршрутов. Формат ORP не меняется. Совместимый ответ содержит `choices`, `usage`,
`costs`, `costSummary`, `economics`, `provenance` и `runId`.

Предлагаются доступные OpenRouter и local_openai маршруты: их текстовые
транспорты делают один inference POST без автоматического платного повтора.
Другие транспорты требуют такой же гарантии перед включением. Модели не
зашиты в код. Для локальной модели действуют обычные admission-проверки GPU/RAM.
Ограничение одного ответа — 1024 выходных токена.

Справочная цена из кэша показывается с предупреждением о возможной давности.
После ответа отображаются фактическая стоимость либо отдельно оценка; отсутствие
цены обозначается как неизвестное. `0` сохраняется как ноль. История вызовов,
стоимость и provenance хранятся в SQLite вместе с ответами; ошибки учитываются
без автоматического повторения. Повтор возможен только явной кнопкой пользователя.

База `data/buzha.sqlite3` сохраняет прежние таблицы. Добавлены только `settings`
и `model_calls` через `CREATE TABLE IF NOT EXISTS`; существующие записи не
переносятся и не удаляются. Для изолированной проверки можно задать `BUZHA_DATA_DIR`.
Контекст запроса ограничен последними 30 сообщениями и до 30 заказов/заданий;
при превышении размера старый контекст сокращается.

## Проверки

```powershell
python -m unittest discover -s apps/server/integrations/buzha -p test_server.py
node apps/server/node_modules/vitest/vitest.mjs run apps/server/src/services/autonomous-apps.test.ts apps/server/src/routes/buzha-model-gateway.test.ts apps/server/src/services/local-runtime-stop-all.test.ts apps/server/test/system-apps.test.ts
node node_modules/typescript/bin/tsc --noEmit -p apps/server/tsconfig.json
pnpm --filter @snarkroute/launcher build
node node_modules/tsx/dist/cli.mjs scripts/smoke-service-endpoints.ts
node apps/server/scripts/smoke-buzha.mjs
```

`smoke-buzha.mjs --chat` дополнительно выбирает модель с нулевыми входной и
выходной ценами в текущем каталоге и делает один явный модельный вызов.
При ошибке скрипт завершается, ничего автоматически не повторяет.

`smoke-buzha-ui.mjs` использует Playwright (`PLAYWRIGHT_MODULE_PATH`, если пакет
доступен вне проекта) и установленный Chrome. Он создаёт временные реестр и
базу, проверяет заказ/задание/выбор модели и сохранение после перезапуска Python,
все вкладки при 1440 px и 390 px, затем настоящую карточку Мастерской и её иконку.
Скриншоты сохраняются в `BUZHA_SMOKE_OUTPUT`. Рабочие заказы пользователя не меняются.
