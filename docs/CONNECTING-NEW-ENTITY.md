# Как подключить новую сущность к SnarkRoute

Шпаргалка для любой нейросети (Codex, Claude, другой агент), которой поручили
«подключи X к SnarkRoute». Цель: не спрашивать владельца про контекст, который
уже зафиксирован здесь. Читать вместе с `AGENTS.md` (режим context-budget).

Владелец: Сергей Козинцев. Репозиторий: `Y:\Процесс\SnarkRoute` (Windows,
PowerShell, pnpm-монорепо, сервер на Fastify + tsx).

## 0. Сначала определи тип сущности

| Тип | Примеры | Куда класть |
| --- | --- | --- |
| A. Облачный провайдер моделей | Polza, OpenRouter, Gemini, Replicate, KIE | `packages/adapters/<name>` + регистрация в сервере |
| B. Локальный GPU/CPU-воркер | `local_upscale`, YuE2, H3, Bonsai, FLUX.3 native | `workers/<name>` + сервис-обёртка в сервере + адаптер |
| C. Инструменты для агентов (MCP) | AE-tools, jabberwock_*, local_runtime_* | `apps/server/src/mcp/<name>-tools.ts` |
| D. Агент или служба со своим UI | Tove (4890), Factory (4891), PersonaCore (8766) | отдельное приложение + запись в реестре портов + плитка в Мастерской |

Часто сущность — это B + C: воркер рисует, а MCP даёт умной модели им рулить.

## 1. Неизменные правила (нарушать нельзя)

1. **Все модельные вызовы идут через SnarkRoute API `127.0.0.1:4317`.** Никто
   (Mixar, агенты, панели AE/Photoshop) не ходит к провайдеру или воркеру
   напрямую. SnarkRoute выбирает провайдера, проверяет доступность, считает
   стоимость и пишет отказы.
2. **Порты задаются только в `service-endpoints.json`.** Сначала новая запись
   там, потом код. Дубли портов считаются ошибкой. Host всегда `127.0.0.1`.
   Подробности в `docs/LOCAL_SERVICE_PORTS.md`.
3. **Без ComfyUI.** Прототип `flux3-comfy` отменён и не используется.
4. **Видеокарта.** Пока владелец за компьютером, фоновая работа агентов не
   занимает GPU. Перед тяжёлым запуском вызывается `local_runtime_admission`
   (intent=workload); предупреждения и блокеры показываются, а не игнорируются.
   Интерактивный запрос самого владельца допустим, но тоже через admission.
5. **Модели не хардкодятся.** Возможности воркера приходят живьём (из его
   `/health` или `/capabilities`) и вливаются в Model Catalog V1. Если весов
   нет, модель показывается как unavailable и не предлагается к выбору.
6. **Веса не скачиваются при старте.** Скачивание делается явным скриптом;
   в `model-registry.json` воркера указаны лицензия, источник, точный URL,
   размер и SHA-256.
7. **Стоимость.** Даже у бесплатного локального провайдера сохраняется
   объект cost (provider/base cost = 0). Экономику и provenance не выкидывать.
8. **Совместимость маршрутов.** Формат `.orp*`/`.route*`, ключи хранилища
   и `.snarknode` без явного решения о миграции не меняются.
9. **Секреты.** Токены лежат в `.env` (сервер перечитывает его при каждом
   старте через лаунчер), в чат и в логи не выводятся.

## 2. Тип B: локальный воркер (эталон: `local_upscale`)

Канонический образец лежит в `workers/local-upscale` + `packages/adapters/local-upscale`
+ `apps/server/src/services/local-upscale-local.ts`. Копируй его устройство,
а не изобретай новое. Путь запроса:

```text
клиент → /api/model-gateway/jobs → route executor → @snarkroute/<adapter> → воркер → PNG-ассет
```

Чек-лист (по файлам, которые трогал `local_upscale`):

1. **Воркер** `workers/<name>/`: Python, `uv`, FastAPI/uvicorn на
   `127.0.0.1:<port>`, долгоживущий процесс (модель держится в памяти, а не
   грузится на каждый вызов). Обязательно:
   - `/health` с `{"service": "<identity>", "ok": true}`;
   - выдача возможностей (какие модели готовы, какие нет);
   - токен в заголовке (`<NAME>_WORKER_TOKEN`);
   - структурные ошибки: CUDA OOM, нет весов, неверный вход, таймаут, отмена;
   - выгрузка модели из VRAM после простоя;
   - `model-registry.json` (см. правило 6), `README.md`, `.env.example`, тесты.
2. **Порт** добавить в `service-endpoints.json` (`watch: "when_running"`,
   `identity`). Проверка: `scripts/smoke-service-endpoints.ts`.
3. **Сервис-обёртка** `apps/server/src/services/<name>-local.ts` и регистрация
   в `local-runtime-supervisor.ts` и `local-service-endpoints.ts`: старт/стоп,
   проверка здоровья, журнал. Тогда воркер виден в Мастерской и чинится
   кнопкой «Перезапустить SnarkRoute» без ручных .bat.
4. **Адаптер** `packages/adapters/<name>/` (`src/index.ts` + `test/`): только
   транспорт к воркеру, без логики UI и маршрутизации.
5. **Регистрация в сервере**: `services/model-catalog-v1.ts` (живые
   возможности), `services/model-routing-policy.ts` и
   `services/semantic-model-selection.ts` (когда выбирать этого провайдера),
   `model-gateway-jobs/service.ts`, `execution/service.ts`,
   `providers/provider-node-manifests.ts` (узел для BoojumRoute),
   `routes/models.ts`. Зависимость добавить в `apps/server/package.json`.
6. **UI** при необходимости: `apps/studio` (параметры узла), пример маршрута.
7. **Флаг включения** `<NAME>_ENABLED=1` в `.env` сервера. Без него провайдер
   выключен; включать только после живого смоук-теста на GPU.
8. **Документ** `docs/<name>.md` по образцу `docs/local-upscale.md`: setup,
   реестр, поведение, границы MVP.

## 3. Тип A: облачный провайдер

Адаптер в `packages/adapters/<name>` (образцы `polza`, `openrouter`, `kie`),
ключ в `.env`, затем пункты 5, 7, 8 из раздела 2. Учитывать стоимость в cost.
Деньги: агенты не просят одобрения на каждую трату; есть один общий лимит на
период, внутри него распределяют сами.

## 4. Тип C: дать умной модели управлять сущностью (MCP)

У SnarkRoute есть собственный MCP-сервер: Streamable HTTP на
`http://127.0.0.1:4317/mcp`, авторизация `Bearer $SNARKROUTE_MCP_TOKEN`
(без токена `/mcp` выключен). Код лежит в `apps/server/src/mcp/`:

- `server.ts` создаёт сервер и вызывает `register*Tools`; там же строка
  `instructions`, её дополняй правилами для новых инструментов;
- `tools.ts` (After Effects), `jabberwock-tools.ts` (маршруты),
  `local-runtime-tools.ts` (`local_runtime_status|admission|start|stop`).

Новые инструменты: файл `apps/server/src/mcp/<name>-tools.ts` + тест рядом +
одна строка регистрации в `server.ts`. Инструменты вызывают **сервисы
сервера** (Model Gateway, supervisor), а не воркер напрямую.

Кто подключён к этому MCP:

- **Codex** (приоритет №1, по подписке): `C:\Users\serge\.codex\config.toml`,
  секция `[mcp_servers.snarkroute-ae]`, `url = "http://127.0.0.1:4317/mcp"`,
  `bearer_token_env_var = "SNARKROUTE_MCP_TOKEN"`. До 21.10 переменной в среде
  не было, и авторизация молча не проходила; теперь она задана на уровне
  пользователя. Codex подхватит её после перезапуска.
- **Claude Code** (приоритет №2, по подписке): подключён в user-scope
  (`~/.claude.json`, сервер `snarkroute`, заголовок
  `Authorization: Bearer ${SNARKROUTE_MCP_TOKEN}`). Сам токен в конфиге не
  лежит, он берётся из пользовательской переменной среды `SNARKROUTE_MCP_TOKEN`
  (её же читает Codex). Claude Code читает `CLAUDE.md`, который импортирует
  `AGENTS.md`. Проверить, что `ANTHROPIC_API_KEY` не задан, иначе Claude Code
  уйдёт на платный API.
- **Claude Desktop и чаты claude.ai на этом компьютере** (по подписке): в
  `%APPDATA%\Claude\claude_desktop_config.json` сервер `snarkroute` запускает
  `scripts/snarkroute-mcp-stdio.ps1`. Скрипт берёт токен из `.env` и через
  `mcp-remote@0.15.2` делает мост stdio→HTTP. Desktop умеет только stdio.
  После правки конфига Desktop нужно перезапустить.
- Если токен меняется: обновить `.env` и переменную среды пользователя, затем
  перезапустить Codex и Claude.
- **ChatGPT** ходит через SnarkBridge (MCP 8767 + туннель 8080). Это отдельный
  мост; маршруты и результаты через веб-композер ChatGPT не таскать.

Инструмент, отдающий картинку модели, должен возвращать MCP-контент типа
`image` (уменьшенное превью), иначе модель не увидит результат и не сможет
его оценить.

## 5. Тип D: агент или служба

Своё приложение (образцы `Y:\Приложения\Tove`, `Y:\Приложения\Factory`),
`/api/health` с identity, запись в `service-endpoints.json` (`watch: "always"`)
и в `paths`, плитка в лаунчере (`apps/launcher`, порт 5172). Правила системы:

- **Все вопросы к владельцу идут только через Секретаря**, в одно окно.
  Ни один агент не пишет владельцу напрямую.
- Агент сам сообщает о простое или поломке (через Секретаря); красная лампа
  в Мастерской.
- Новые дизайны Фабрики сначала показываются владельцу превью через
  Секретаря на одобрение. «Маг» — авторская работа, в продажу не идёт.

## 6. Ветки, проверки, отчёт

1. Работать в ветке `build/<YYYY-MM-DD>-<тема>`.
2. Перед сложным поведением писать тесты. Запускать сфокусированные проверки:
   vitest затронутого пакета, `tsc --noEmit -p apps/server/tsconfig.json`,
   pytest воркера.
3. Готовую и проверенную ветку **сразу мержить без вопросов владельцу**,
   перезапускать службы и удалять смёрженные ветки.
4. После правок кода: `graphify update .`.
5. Ночная или крупная работа: отчёт `NIGHT_REPORT_<дата>-<тема>.md` в корне
   (что сделано, что проверено, что заблокировано и почему).

## 7. Пример целиком: локальный генератор изображений (2026-10-21)

Умная модель по подписке (Codex, затем Claude) работает арт-директором:
ставит задачу, смотрит превью, исправляет и повторяет. Рисует локальная
FLUX.3 Klein. Подробности в `workers/flux3-native/README.md`.

| Слой | Где |
| --- | --- |
| Воркер (тип B) | `workers/flux3-native/worker.py`, порт 8093, токен `FLUX3_WORKER_TOKEN` |
| Жизненный цикл | `services/flux3-native-local.ts`, рантайм `flux3` в супервизоре |
| Провайдер | `providers/flux3-native.ts`: admission → воркер, иначе одноразовый CLI |
| Gateway | `ai.image.generate` + provider `flux3_native` (уже был) |
| MCP (тип C) | `mcp/image-tools.ts`: `image_generate`, `image_job`, `image_cancel`, `image_view` |
| Клиенты | Codex, Claude Code, Claude Desktop/claude.ai (раздел 4) |
| Живая проверка | `apps/server/scripts/mcp-image-smoke.ts ["промпт"]` |

Включено (`FLUX3_NATIVE_ENABLED=1`) 21.10 после смоука. Сквозной вызов через
MCP занимает 46–52 с с холодного старта, видеопамять в пике ~11 ГБ; по простою
воркер завершается и освобождает RAM.

**Второй провайдер: Qwen-Image-Edit-2511** (`workers/qwen-image-edit`, 21.10).
Пример подключения готового движка без Python: официальная сборка
stable-diffusion.cpp (`sd-server`), веса GGUF, сервис `services/qwen-edit-local.ts`
(порт 8094, рантайм `qwen_edit`, выход по простою на стороне SnarkRoute, потому что
у `sd-server` его нет), провайдер `providers/qwen-edit-local.ts` (нативная очередь
`/sdcpp/v1/img_gen`), MCP `provider: "qwen_edit_local"`. Замер: правка 512×512 за
~95 с, пик VRAM ~15,3 ГБ из 16, пик RAM ~13,7 ГБ. Уроки: флаги сверять с `-h`
бинарника, а не с документацией; нативным программам передавать относительные
ASCII-пути (репозиторий лежит в `Y:\Процесс`); большие файлы с Hugging Face
качать через `hf_xet`, а не одним потоком curl (12–16 МБ/с против 1,5).

## 8. Как не забывать о возможностях

Новая возможность считается подключённой, только когда о ней знают все умные
модели без напоминаний владельца:

1. **MCP-инструмент с понятным `description`** и строка в `instructions`
   сервера (`mcp/server.ts`): любой клиент получает её при подключении.
2. **Строка в `CLAUDE.md`** (раздел «What you can drive right now») и, если
   меняются правила, в этом файле.
3. **Живой смоук-скрипт** рядом с кодом, чтобы любой агент мог убедиться,
   что возможность работает, а не только числится.
4. **Отчёт** `NIGHT_REPORT_*` или запись в Notion/Секретарю, если владелец
   должен что-то решить.
