# Технорадар

Технорадар встроен в локальные SnarkRoute и BoojumRoute. Открыть: кнопка
«Технорадар» или `/tech-radar` (обычно `http://127.0.0.1:5174/tech-radar`
для SnarkRoute). API: существующий сервер `http://127.0.0.1:4317/api/tech-radar`.

Вставьте публичную GitHub-ссылку, нажмите «Исследовать» и откройте карточку.
Обычная повторная ссылка открывает тот же проект. «Повторно исследовать» создаёт
новое исследование внутри него. Рекомендация модели и решения владельца хранятся
отдельно. Кнопки решений и комментарий действительно сохраняются.
«Подготовить тест» сохраняет решение и план, не запуская эксперимент.

## Источники и модель

Приём ссылок выделен в GitHub-адаптер; проект имеет `sourceType` и `sourceKey`
для добавления других источников. Ключ не зависит от регистра, `.git`, фрагмента
и пути к файлу внутри репозитория.

Коллектор обращается только к `https://api.github.com/repos/...` без авторизации.
Не следует перенаправлениям и ссылкам README, ограничивает размер, время и
количество запросов, использует постоянный кеш и ETag. Метаданные, README,
дерево, последние релизы и выборка issues дополняются максимум восемью файлами:
корневыми лицензиями, VERSION, CHANGELOG, зависимостями и документацией
Director/API/оборудования. Недоступные необязательные источники становятся
предупреждениями. Приватные репозитории не обходятся через локальные учётные
данные. Код, установщики и зависимости исследуемых проектов не исполняются.

Анализ использует существующий `createDefaultRadarModelInvoker`. Добавлен
`codex-subscription`, использующий обнаружение CLI из `codex-desktop.ts`
и транспорт CLI радаров. По умолчанию используется Codex через подписку ChatGPT
и модель по умолчанию CLI. `SNARKROUTE_TECH_RADAR_PROVIDER=claude-subscription`
позволяет выбрать существующий Claude по подписке. Перехода на платный API нет.
Настройки остальных трёх радаров не меняются.

Для Codex отключены команды, приложения, браузер, MCP, дополнительные агенты,
проектные инструкции и пользовательская конфигурация; включены read-only и
ephemeral. Состояние CLI находится внутри данных Технорадара. Вход использует
действующий access token существующей подписки: временный файл удаляется при
завершении; refresh credential владельца не копируется и не вращается.
При истёкшем входе требуется актуальная сессия Codex. Claude тоже работает с
отключёнными инструментами, MCP и настройками в изолированной папке.

Модель получает публичные источники и сокращённый список названий и возможностей
мастерской. Секреты, `.env`, локальные конфигурации и пути к ним в запрос не входят.
JSON-схема и Zod проверяют результат. Содержательные записи имеют тип вывода,
идентификатор полученного источника и цитату. README остаётся заявлением автора;
документация не доказывает успешный локальный тест. Проверяется наличие цитаты,
а не истинность любого пересказа. После одной попытки исправления неподтверждённые
выводы становятся неизвестными, соответствующие возможности исключаются.
Если содержательное описание и возможности подтвердить не удалось, задание
завершается ошибкой с сохранёнными источниками.

## Хранение и очередь

Данные: `data/radars/tech-radar/` относительно корня репозитория:

- `catalog.json`: проекты, исследования, источники, связи возможностей, решения,
  очередь, уведомления и настройки наблюдения;
- `catalog.backup.json`: предыдущий записанный снимок;
- `github-cache/`: публичные ответы API и ETag;
- `catalog.lock`: идентичность процесса, владеющего очередью;
- `analysis-sandbox/`: изолированное состояние CLI;
- `last-smoke.json`: исторический результат последнего живого smoke-скрипта.

Использован принятый в H3Queue подход: последовательная очередь, JSON-снимки и
атомарная замена файла. Ошибка переименования не затирает старый каталог.
Повреждённый каталог автоматически не сбрасывается: резервную копию можно
восстановить вручную после остановки владельца блокировки. Процессная блокировка
не допускает конкурентной записи сервером и smoke-скриптом. Блокировка умершего
процесса восстанавливается. Незавершённые исследования возобновляются,
завершённые не повторяются.

Каждая связь «проект — возможность» имеет постоянный id и уровень `declared`,
`documented` или `local_test`. Карту собирает `capabilityCatalog`. Начальная
инвентаризация читает общий реестр сервисов и декларативные узлы обработки.
Эти локальные инструменты считаются непроверенными. Карта мастерской частичная:
«новое для каталога» не доказывает отсутствие аналогов. При открытии сервера
сравнение последнего исследования пересчитывается по актуальному каталогу;
исходные находки и решения сохраняются.

Движок ограничивает «Внедрить» до «Испытать»/«Следить»: в MVP нет интерфейса
внесения протокола успешного локального эксперимента. Кнопка «Внедрение
рассмотреть отдельно» сохраняет отдельное решение, без установки.

Наблюдение по умолчанию выключено, интервал — семь дней. Проверяются только
проекты с решением/рекомендацией «Следить» и включённым наблюдением. Используется
существующий `startRadarScheduler` с пустым списком платных радаров и локальным
callback. Уведомления появляются внутри Технорадара при изменениях возможностей,
лицензий, требований, интеграции, рисков или архивации. Переформулировка тех же
цитат не создаёт уведомление. Внешние сообщения не отправляются.

## API и MCP

- `GET /api/tech-radar`: каталог, очередь и карта;
- `POST /api/tech-radar/projects`: `{url, repeat?: boolean}`;
- `GET /api/tech-radar/projects/:id`: карточка и история;
- `POST /api/tech-radar/projects/:id/decisions`: `{status, note?}`;
- `PATCH /api/tech-radar/projects/:id/watch`: `{enabled, intervalDays?}`;
- `POST /api/tech-radar/projects/:id/acknowledge`: просмотр изменений;
- `GET /api/tech-radar/capabilities`: карта возможностей.

Решения: `skip`, `watch`, `test`, `review_integration`. Облачный режим не
регистрирует API Технорадара. Локальный режим использует общую HTTP-границу.
Отказ при загрузке каталога не останавливает остальные функции сервера.
MCP-инструменты `tech_radar_research` и `tech_radar_catalog` зарегистрированы
в существующем авторизованном `/mcp`; правила добавлены в инструкции и `CLAUDE.md`.

## Проверки и следующий этап

Живой сценарий: `node node_modules/tsx/dist/cli.mjs apps/server/scripts/smoke-tech-radar.ts`.
Запускайте при остановленном основном владельце каталога: блокировка откажет в
конкурентной записи. Для нового исследования добавьте `--repeat`.
Автоматические тесты используют поддельные ответы GitHub/моделей.

Далее: протоколы локальных проверок и подтверждённое внедрение, полная
инвентаризация провайдеров/DCC-инструментов, другие типы ссылок и SQLite при
росте каталога. JSON-снимки рассчитаны на личную мастерскую.
